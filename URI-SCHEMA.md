# URI Schema - Student API

| Method | URI                        | คำอธิบาย                                            | Status Code ที่เป็นไปได้ |
| ------ | -------------------------- | --------------------------------------------------- | ------------------------ |
| GET    | /                          | ตรวจสอบสถานะ Student API                            | 200                      |
| GET    | /api/v1/students           | ดึงรายการนักศึกษาทั้งหมด                                | 200                      |
| GET    | /api/v1/students/{id}      | ดึงข้อมูลนักศึกษารายบุคคล (รองรับ ?include=courses)       | 200, 404                 |
| POST   | /api/v1/students           | เพิ่มข้อมูลนักศึกษาใหม่                                   | 201, 400, 409            |
| PUT    | /api/v1/students/{id}      | แก้ไขข้อมูลนักศึกษาทั้งระเบียน                             | 200, 400, 404            |
| PATCH  | /api/v1/students/{id}      | แก้ไขข้อมูลนักศึกษาบางส่วน                               | 200, 404                 |
| DELETE | /api/v1/students/{id}      | ลบข้อมูลนักศึกษา                                       | 200, 404                 |
| GET    | /api/v1/students/{id}/full | ดึงข้อมูลนักศึกษาพร้อมรายวิชาที่ลงทะเบียน                    | 200, 404                 |
| POST   | /graphql                   | เรียกใช้งาน GraphQL Endpoint                           | 200                      |

# Peer Check และแก้ไขตามข้อเสนอแนะ

### ชื่อ-นามสกุลผู้ตรวจสอบ (ผู้กรอกแบบฟอร์ม): จุฑาบดี วิชัย

| หัวข้อตรวจสอบ                                                  | ผ่าน / ไม่ผ่าน            | ข้อเสนอแนะ                                                                    |
| -------------------------------------------------------------- | ----------------------| ----------------------------------------------------------------------------- |
| URI ใช้คำนามพหูพจน์ ไม่มีคำกริยาปน                                  | ผ่าน                   | ใช้ `students` ซึ่งเป็นคำนามพหูพจน์ถูกต้อง                                    |
| ใช้ตัวพิมพ์เล็กและขีดกลาง ไม่ใช้ camelCase หรือ underscore             | ผ่าน                    | URI ใช้ตัวพิมพ์เล็กทั้งหมด ไม่มี camelCase หรือ underscore                    |
| HTTP Method สอดคล้องกับการดำเนินการ                               | ผ่าน                   | ใช้ GET, POST, PUT, PATCH และ DELETE ได้เหมาะสมตามหลัก REST                   |
| Status Code ครอบคลุมทั้งกรณีสำเร็จและกรณีผิดพลาด                    | ผ่าน                    | มีการกำหนด 200, 201, 400, 404 และ 409 ครบถ้วน                                 |
| ความสัมพันธ์ระหว่าง resource แสดงด้วย nested path อย่างเหมาะสม       | ผ่าน                    | ใช้ `/api/v1/students/{id}/full` เพื่อดึงข้อมูลเพิ่มเติมของนักศึกษาได้เหมาะสม |
